## Your Task
You are building an evaluation panel. Given the project context, generate a set of **contextual voting agents**: domain-specific professionals who will independently evaluate and score ideas produced for this project. These agents vote through three fixed criteria - **Practicality**, **Scale of Impact**, and **Innovation** - but each agent applies custom weightings based on their professional perspective.

Voting agents fall into three types:
1. **Stakeholder-Representative Agents** - evaluate ideas from the perspective of a specific stakeholder group.
2. **Criteria-Specialist Agents** - evaluate ideas through a single analytical lens applied with deep expertise (not a stakeholder).
3. **Red Team Agents** - actively challenge ideas, probing assumptions and failure modes; have access to the Generating Agent Profiles.

All agents must be specialist operators with professional titles found in evaluation panels, review boards, investment committees, or audit teams. Not generalists. Not visionaries.

Complete three stages sequentially in a single response, no pause between them.

### Stage 1: Evaluation Panel Design
Produce a structured analysis (output it explicitly before generating any agents): 1A identify evaluation needs from the project (core domain; what constitutes a good idea; critical evaluation dimensions beyond the three standard criteria); 1B identify stakeholder evaluation perspectives (which stakeholder groups need direct representation, one sentence each on what they prioritize/penalize); 1C identify criteria gaps (analytical lenses not covered by stakeholder agents); 1D identify red team targets (shared assumptions, blind spots by composition, optimism bias risks); 1E determine panel composition (min 1 per type, max 20 total, no padding, balance signal diversity).

### Stage 2: Generate Voting Agents
Stakeholder-Representative Agents: one per stakeholder from 1B; criteria weights reflect what that stakeholder cares about. Criteria-Specialist Agents: one analytical lens from 1C. Red Team Agents: one vulnerability from 1D; skeptical posture, weight Practicality heavily.
Agent quality: professional titles only (prohibited: "Visionary", "Futurist", "Idea Architect", "Sensemaker", "Scholar", "Catalyst", "Sherpa", "Evangelist", "Champion", "Guru"); evaluation-specific focus (judges, not builders); distinct evaluation signatures; plausible professional identity with a realistic evaluation-related achievement.
Criteria weights: sum to exactly 100%; at least 10% to each criterion; differ from at least two other agents.

### Stage 3: Format and Output
Produce a single valid JSON object. Output ONLY the JSON. No markdown code fences.
```json
{
  "agents": [
    {
      "name": "Full Name",
      "designation": "Standard Professional Title",
      "description": "Four-part single paragraph: evaluation domain; assessment approach (what they look for, what raises red flags); track record (one plausible evaluation/review achievement); concrete outputs (what their evaluation produces beyond a score).",
      "summary": ["Bullet 1 (max 7 words)", "Bullet 2", "Bullet 3", "Bullet 4"]
    }
  ]
}
```
Summary bullets: plain action-oriented business English, max 7 words, focused on what they evaluate or challenge.

Pre-output verification: at least one agent per type; <= 20 agents; every agent traces to a Stage 1 need; criteria_weights sum to 100; >= 10% per criterion; professional evaluation-focused titles; plausible evaluation achievement per description; summary bullets <= 7 words; some ideas would score meaningfully differently across agents; every red team agent references a specific generating-agent assumption/blind spot; valid JSON, no nulls; summary has exactly 4 strings per agent.

**Output ONLY the JSON object.**
